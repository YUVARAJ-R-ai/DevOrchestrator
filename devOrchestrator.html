Core philosophy
Human owns the thinking.
Orchestrator owns the plumbing.

60% of a sprint is friction — branch setup, PR mechanics, research, context switching. DevOrchestrator absorbs that friction through two sequential AI sessions coordinated by a lightweight Python CLI.

01

Artifact-driven

A Claude Code research session reads your actual codebase and produces a structured artifact — sub-tasks, files to touch, acceptance criteria. The artifact is the handoff between AI sessions and the record of what was planned.

02

Two-session AI

Session one researches and plans. Session two implements. Both run in tmux panes you can watch live — no black box. Claude Code Pro subscription only, no API key required.

03

Two human gates

Pick your task. Review the implementation. That's it. Branch creation, artifact generation, coding, checks, PR, TL approval, deploy, and task close are all automated between those two moments.

The handoff document
The artifact

The research session writes it. The implementation session reads it. The TL reviews it alongside the diff. It's the plan, the spec, and the audit trail — one markdown file.

# Artifact: Implement JWT Authentication
_Task: PROJ-42 | Branch: feature/jwt-auth | Generated: 2026-06-10_

## Context (from research session)
- Existing pattern: src/middleware/auth.py uses session-based approach
- JWT library already installed: python-jose==3.3.0
- Risk: session store is not thread-safe — switching to stateless JWT resolves this

## Sub-tasks
- [ ] Create User model with email + hashed password
- [ ] Implement JWT generation helper (use existing python-jose)
- [ ] Add POST /auth/login endpoint
- [ ] Write auth middleware for protected routes
- [ ] Write unit tests for all endpoints

## Files to Create / Modify
- src/models/user.py — add User model
- src/routes/auth.py — new: login + register
- src/middleware/jwt.py — new: token validation
- tests/test_auth.py — new: endpoint tests
Model architecture
Three roles.
No API key required.

Claude Code Pro subscription powers both AI sessions. DeepSeek V4 Flash handles PR descriptions and future intelligence features. No Claude API key — just the CLI you already have.

Research session

Claude Code CLI

Reads your codebase with file + bash tools. Understands patterns. Writes the artifact. Runs in tmux pane 1.

Pro subscription · no API key · claude -p
Implementation session

Claude Code CLI

Reads the artifact. Implements every sub-task. Checks them off as it goes. Runs in tmux pane 2.

Pro subscription · no API key · claude -p
External intelligence

DeepSeek V4 Flash

PR description generation from git log + artifact. Reserved for chatbot, mesh queries, and future intelligence features.

Layer 2 — the novel part
Shared context mesh

SQLite + JSON on the shared server, ~50 lines of Python. Every dev's orchestrator reads and writes to it — so the team thinks as one brain and merge collisions are caught before they happen.

✎

Writes on task start

Logs which modules you're touching, which task, your branch. Other orchestrators see it instantly.

☉

Writes on decisions

"Switching JWT to session-based" — logged with devorchestrator decision. Every co-pilot queries this before acting.

⚠

Conflict detection

Dev 2 touches a module Dev 1 is refactoring? Warning surfaced before a single line is written. Not a block — a nudge.

↻

Team visibility

devorchestrator mesh shows a live table: who is on what task, what modules are active, recent decisions.

Layer 3 — rate limit bypass
Account rotation with tmux

Each tmux pane is one authenticated session. When Account A hits a rate limit, the orchestrator detects it in stderr and silently routes to Account B. No crash, no lost work, no manual intervention.
