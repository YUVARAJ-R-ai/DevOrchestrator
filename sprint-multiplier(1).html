Core philosophy
Human owns the thinking.
Orchestrator owns the plumbing.

Out of a 10-day sprint, only ~4 days is actual feature work. The other 6 is friction — branch setup, PR mechanics, waiting on review, context switching. The orchestrator absorbs that friction.

01

Shared context mesh

Every dev's AI co-pilot reads and writes to a shared memory bus. The team thinks as one brain — conflicts caught before they happen, not after a merge war.

02

Plug and play

One YAML config file per team member. Point at the shared infra, pick your agent (claude / agy / codex), go. Zero onboarding friction.

03

Human-in-the-loop

The TL approval gate is the only manual checkpoint. Everything before and after is automated. Creative decisions stay with humans — always.

The pipeline — two tracks
Same orchestrator.
Different infrastructure.

The orchestrator is agent-agnostic and infra-agnostic. The same 7-stage pipeline runs on fully open source tools or on Azure DevOps — just swap the config.

Layer 2 — the novel part
Shared context mesh

The thing that doesn't exist in any tool yet. Every co-pilot reads and writes a shared memory bus — SQLite + JSON on the shared server — so the team thinks as one brain.

✎

Writes on task start

Logs which modules you're touching, which task, your branch. Other co-pilots see it instantly.

☉

Writes on decisions

"Switching JWT to session-based" — logged automatically. Every co-pilot queries this before acting.

⚠

Conflict detection

Dev 2 touches a module Dev 1 is refactoring? Warning surfaced. Not a block — a nudge. Humans decide.

↻

Reads before acting

"Has anyone touched auth/ this sprint?" — answered before the first line of code. Collision avoided.

Layer 4 — rate limit bypass
Account rotation with tmux

Each tmux pane = one authenticated session. When Account A hits a rate limit, the orchestrator routes to Account B. No crash, no lost work.

The config — plug and play
One file. Any track.

Execution plan
Build order

Start small. Get the innermost loop working first, then expand outward.

Per-dev co-pilot loop

Just you, one task, claude -p as subprocess, auto-checks, auto-PR. Get the inner loop working on your machine.

Day 1-2

Shared infra stack

Docker Compose: Plane + Gitea + Woodpecker + Coolify (or connect to Azure DevOps). Run it on your homelab Debian server via Tailscale.

Day 3-4

Shared context mesh

SQLite + JSON on the shared server. ~50 lines of Python. Each co-pilot writes events, queries before acting.

Day 5

Account rotation

Tmux session pool router. Rate limit detection, automatic account switching. Add when you actually hit limits.

Day 6

Team rollout

Give each dev the orchestrator binary + their yaml config. They plug in, they're live. No training needed — the orchestrator watches, not commands.
